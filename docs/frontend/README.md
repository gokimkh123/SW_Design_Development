## 개발 방법

- `/api` 요청은 Vite 프록시를 통해 `http://localhost:8000`으로 전달 ([API 명세서 8장](../common/API.md#8-로컬-개발-연결))
- 백엔드 준비 전에는 API 명세서 JSON 예시 기반 mock으로 개발 (`VITE_USE_MOCK=true`)
- 설문 문구 하드코딩 금지, `GET /api/survey` 응답 기반 렌더링

## 실행

- Node.js 20.19 이상(또는 22.12 이상) 필요
- 아래 명령은 프로젝트 루트 기준
- 팀원별 clone · Windows 명령 · 백엔드 연결: [로컬 개발 실행 가이드](../common/LOCAL_DEVELOPMENT.md)

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev
```

- `VITE_USE_MOCK=true`: 임시 설문 · 후보 · 추가 화면 데이터 사용
- `false`: 실 API 호출. 현재 백엔드는 사용자·설문·페르소나·후보 추림과 시뮬레이션 시작/상태/SSE/완료 리포트, 매칭·생활 규칙 조회/동의 경로를 제공한다. 프론트엔드 A1→C2 실서버 완주는 아직 검증하지 않았다.
- 후보 조회 응답의 `simulation`은 아직 항상 `null`이다. 다른 세션·기기에서 실행 상태를 복원하려면 백엔드 연결이 추가로 필요하다.
- 실제 엔진은 미연결이며 기본 `ENGINE_IMPL=fake`는 개발용 결과를 만든다. `replay` 데이터·재생도 아직 준비되지 않았다.
- P2 미리보기 · 관리자 데모는 실제 모드에서 비활성
- 임시 설문 문구 · 선택지는 승인된 시드 데이터로 교체 필요

실연동 확인 시 백엔드를 `localhost:8000`에서 실행하고 `frontend/.env`의 `VITE_USE_MOCK=false`로 설정한 뒤 Vite를 재시작한다. 배포 환경의 API 버전은 별도로 확인해야 한다. 로컬 백엔드 테스트 통과나 mock 완주를 실서버 화면 완주로 간주하지 않는다.

```bash
npm run typecheck
npm test
npm run build
```

- mock 모드의 `우리 방` · `전체` 탭은 추가 화면 미리보기로 이동
- D4 관리자는 `전체`의 **데모 전용** 메뉴에서만 진입, 비식별 예시 집계만 표시
- 실제 인증 · 호실 배정 완료로 오인될 수 있는 문구 미표시

## 멤버십 · 반응형 · 후보 카드 개선 (11/1)

- **멤버십 화면** (`features/PlansScreen.tsx`, 하단 탭 · PC 메뉴 `멤버십`, 리포트의 "플러스 멤버십 알아보기"): 베이직(무료) · 플러스(학기 패스 9,900원 / 월간 2,900원) · 생활관(입사생 1인당 학기 2,000원). 결제 미연동, `PUT /api/subscriptions/me`로 사전 신청만 기록하고 취소 가능. 아직 없는 기능은 "곧 출시"로 표시
- **반응형** (`features/responsive.css`, `main.tsx`에서 마지막에 불러옴): 모바일(~639px) 기존 화면 · 태블릿(640~1023px) 720px 단일 열 · PC(1024px~) 왼쪽 메뉴 + 넓은 본문. PC에서 후보 · 멤버십 3열, 리포트 · 후보 비교 · 페르소나 · 생활 규칙 2열, 설문 · 시뮬레이션 · 매칭은 가운데 좁은 단. 화면별 규칙은 `AppShell`의 `step-{화면}` 클래스로 지정
- **후보 카드** (`features/CandidateCard.tsx`): 진행 순서 안내(후보 고르기 → 7일 가상 동거 → 궁합 리포트), 상태 표시(시작 전 · 진행 중 n/20 · 완료 · 중단), 눈에 띄는 실행 버튼, 최고 점수 후보 "추천" 표시
- 제목 굵기: Tailwind 기본 스타일이 h1~h3 굵기를 초기화해 화면 제목이 가늘게 보이던 문제 수정
- 실제 서비스 문구로 정리(11/1): "발표회 체험용" 등 데모 안내 제거. 결제는 연동하지 않으므로 멤버십은 출시 전 사전 신청으로 안내("정식 출시 전까지는 결제 없이 모든 기능 이용")
- **메신저형 대화 재생** (`features/ChatPlayback.tsx`, 11/1): 서버 이벤트는 그대로 받고 화면 표시만 늦춤. 장면 카드 → 말하는 쪽 "입력 중(•••)" 표시(글자 수 비례 0.9~2초) → 메시지 → 판정 순서, 보통 속도 기준 약 2~3분. "2배 빠르게" · "대화 모두 보기", 서버 완료 후에는 "대화 건너뛰고 리포트 보기". 이미 끝난 실행을 다시 열면 즉시 전부 표시
- **DAY 단위 보기**: 진행 화면에 DAY 구분선과 DAY 1~7 이동 버튼(현재 DAY 강조, 위로 이동 시 "최신 대화 보기"), 대화 다시 보기 화면은 DAY별 필터
- 점검 반영(11/1 밤): DAY 이동 시 자동 따라가기 해제, 멤버십 확인 창 안 오류 표시, 새로고침한 완료 실행은 즉시 전부 표시, 다른 화면에서는 재생 타이머 정지, 요청 중 화면을 옮기면 응답 후 강제 이동 안 함, 후보 목록 수신 전 "후보 없음" 미표시, 리포트 다시 확인 시 실행 정보 함께 조회, 매칭 상태 확인 중복 요청 방지
- 글꼴: Pretendard(OFL) 가변 글꼴 npm 패키지(`pretendard`), 글자 범위별 분할 파일을 빌드 자산으로 제공

## 출시판 갱신: 후보 6명 · 이용권 · 궁합 진단 (11/2)

- 정식 출시 상태를 전제로 문구를 정리함. "사전 신청 · 곧 출시" 안내를 제거하고, 탭 이름을 `멤버십`에서 `이용권`으로 변경함
- **후보 6명**: 후보 카드 3열 × 2행(PC), 아바타 색 6종(`flow.css`의 `flow-avatar--0~5`), 후보 비교 그래프 6색. 선택 후보 외에는 선을 옅게 표시하여 겹침을 줄임
- **이용권 화면** (`features/PlansScreen.tsx`): 남은 가상 동거 횟수, 베이직(무료 3회) · 플러스 이용권(5회 2,900원 / 15회 6,900원) · 생활관(입사생 1인당 학기 2,000원, 도입 요청), 구매 내역. 구매 확인 창은 카드 정보 등 결제 정보를 입력받지 않음
- **횟수 소진 안내**: 시뮬레이션 시작이 `402 PASS_REQUIRED`이면 후보 화면에 안내와 "이용권 보러 가기" 버튼을 표시함. 후보 화면 상단에 남은 횟수 표시(누르면 이용권 화면)
- **궁합 진단** (`features/DiagnosisScreen.tsx`, 화면 `diagnosis`): 잘 맞는 후보 수, 습관 조정 시 늘어나는 후보 수, 점수를 낮추는 성향 3개(내 위치 · 다른 학생 중앙값 · 조정 제안). 후보 화면 하단 진입 카드는 잘 맞는 후보가 2명 이하이거나 완료한 가상 동거 3건 이상이 모두 60점 미만이면 경고 형태로 강조함. 리포트 점수 60점 미만이면 "궁합 점수가 낮은 이유 확인하기" 링크를 표시함
- mock(`mocks/client.ts`)에도 후보 6명, 무료 3회 한도, 이용권 구매, 진단 예시 응답을 반영함
